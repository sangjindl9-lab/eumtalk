# 설치·운영 설명서

## 1. 필요한 것

| 대상 | 버전 |
|---|---|
| Node.js | 20 이상 (시험: 22) |
| PostgreSQL | 16 |
| Redis | 7 (없어도 서버 1대로는 동작) |
| Flutter | **3.47 이상** (CI 빌드 기준: 3.50.0). Material 위젯이 `material_ui` 패키지로 분리된 버전부터 지원 |
| Python 3 | `mobile/tool/bootstrap.py` 실행용 (`pip install pillow` 하면 아이콘도 교체) |

## 2. 서버 로컬 실행

```bash
docker compose up -d db redis
cd server
cp .env.example .env
npm ci
npm run start:dev
```

- 시작할 때 `migrations/*.sql` 을 이름순으로 한 번씩 자동 적용합니다. 수동 적용은 `npm run migrate:dev`(개발) / `npm run migrate`(빌드 후).
- 상태 확인: `GET /health`, 앱 설정: `GET /v1/app-config`

### 환경변수

| 이름 | 설명 |
|---|---|
| `APP_ENV` | `development` / `staging` / `production` |
| `DATABASE_URL`, `DATABASE_SSL` | PostgreSQL 연결 |
| `REDIS_URL` | 접속 상태·속도 제한·서버 간 실시간 이벤트 전달. 비우면 메모리 방식 |
| `IDENTITY_PROVIDER` | `dev`(개발·시험 전용) / `none` / 계약한 사업자 이름 |
| `DATA_KEY` | 휴대폰 번호 암호화 키. 64자리 16진수 또는 32자 이상 문자열 |
| `PHONE_PEPPER` | 휴대폰 번호 해시용 비밀값 |
| `ADMIN_TOKEN` | 관리자 웹 접속 값 |
| `CORS_ORIGINS` | 관리자 웹 주소(쉼표 구분). 비우면 전체 허용 |

### 개발용 계정 만들기

```bash
npm run dev:accounts -- http://localhost:3000 4
```

`01000001001`부터 차례로 만들어집니다. 앱에서 같은 번호 + 인증번호 `000000`으로 로그인합니다.
앱에서 새 번호로 직접 가입해도 됩니다(시험 환경에서는 인증번호 000000, 성인 확인은 출생 연도 입력).

### 본인확인과 환경

- `development`·`staging`: 개발용 테스트 인증을 쓸 수 있습니다.
- `production`: 테스트 인증은 **거부**됩니다. 본인확인 사업자 설정이 없으면 서버는 뜨지만 **신규 가입·로그인 인증이 503으로 중단**되고,
  서버 로그와 관리자 웹 "조치가 필요한 설정"에 누락이 표시됩니다.
- 사업자가 정해지면 `server/src/auth/identity.ts` 의 `IdentityProvider` 구현을 하나 추가합니다
  (인증번호 발송, 성인 확인 결과를 **서버가 인증기관에서 직접 조회**).

## 3. 통합 시험

```bash
cd server
TEST_DATABASE_URL=postgres://eumtalk:eumtalk@localhost:5432/eumtalk_test \
TEST_REDIS_URL=redis://localhost:6379 npm test
```

시험용 DB를 **비우고** 시작하므로 반드시 별도 DB를 쓰세요(`createdb eumtalk_test`).

## 4. 모바일 앱

```bash
cd mobile
python3 tool/bootstrap.py      # android/·ios/ 생성, 권한·앱 이름·아이콘 반영
flutter pub get
flutter run --dart-define=API_BASE_URL=http://192.168.0.10:3000
```

- `android/`, `ios/` 는 저장소에 넣지 않고 스크립트가 현재 Flutter 버전에 맞춰 만듭니다. 서명 설정을 넣기 시작하면 `mobile/.gitignore` 의 두 줄을 지우고 커밋하세요.
- 에뮬레이터에서 PC의 서버: Android `http://10.0.2.2:3000`, iOS 시뮬레이터 `http://localhost:3000`
- 실기기 두 대: 같은 Wi-Fi의 PC IP 또는 Render 주소를 사용. 시험용 빌드는 첫 화면에서 **앱 이름을 길게 누르면** 서버 주소를 바꿀 수 있습니다
  (스토어 제출용은 `--dart-define=ALLOW_SERVER_OVERRIDE=false`).
- 테스트 APK: `flutter build apk --release --dart-define=API_BASE_URL=https://<서버주소>` → `build/app/outputs/flutter-apk/app-release.apk`
  GitHub에 올리면 Actions의 "Android 테스트 APK" 작업이 같은 일을 하고 APK를 Artifacts에 올립니다.
- Play 제출용 AAB와 iOS TestFlight는 서명 키·Apple 계정이 필요합니다. 지금 생성되는 release APK는 디버그 키로 서명된 **시험용**입니다.

### 앱 이름·색상·아이콘·운영사 정보 바꾸기

`brand/brand.json`(과 `brand/icon.png`)만 고친 뒤 `python3 mobile/tool/bootstrap.py` 를 다시 실행하고 서버를 재시작합니다.

## 5. 관리자 웹

```bash
cd admin && npm ci
API_BASE_URL=http://localhost:3000 npm run dev      # http://localhost:3100
```

**처음 접속**: 관리자 계정이 하나도 없으면 첫 화면이 "소유자 계정 만들기"로 뜹니다. 서버의 `ADMIN_TOKEN` 값과 사용할 이메일·비밀번호(10자 이상)를 입력하면 소유자 계정이 생깁니다.
(서버 환경변수 `ADMIN_EMAIL`·`ADMIN_PASSWORD` 를 넣어 두면 서버가 시작할 때 자동으로 만듭니다.)

| 역할 | 할 수 있는 일 |
|---|---|
| 소유자 | 전체 + 관리자 계정 관리 + 열람·조치 기록 조회 |
| 신고 처리 | 신고 증거 열람·조치, 이의신청, 회원 정지, 그룹방·게시물 관리 |
| 고객 지원 | 회원 조회, 운영 공지, 문의 답변 |
| 정산 | 포인트 원장·조정, 결제·환불 조회, 가격 설정 |

- 개인 대화를 검색·열람하는 기능은 없습니다. 대화 내용은 **신고에 묶인 사본만**, 신고 처리 권한자가 건별로 열 때 보이고 그때마다 기록(`admin_audit_log`)이 남습니다.
- 상설 지역방은 관리자 웹 "그룹방 → 상설 지역방 개설"에서 만듭니다(지역 코드는 `migrations/002_*.sql` 참고, 예: 원주시 `gangwon-02`).
- 유료 기능 가격과 하루 무료 제공량은 "가격 설정"에서 바꿉니다.

## 5-1. 외부 연동 설정

| 연동 | 설정 | 설정 전 동작 |
|---|---|---|
| 본인확인(휴대폰·성인) | `IDENTITY_PROVIDER=portone` + `PORTONE_STORE_ID`·`PORTONE_IDV_CHANNEL_KEY`·`PORTONE_API_SECRET` | 개발·시험: 인증번호 000000 / 운영: 가입 중단 |
| 사진 저장소 | `STORAGE_DRIVER=s3` + `S3_*` | 서버 디스크에 저장(재배포 시 사라질 수 있음) |
| 푸시 발송(서버) | `PUSH_PROVIDER=fcm` + `FCM_SERVICE_ACCOUNT`(서비스 계정 JSON 한 줄) | 발송 기록(push_log)만 남김 |
| 푸시 수신(앱) | 빌드 시 `--dart-define` 으로 Firebase 값 5개(아래) | 푸시 없이 동작(앱이 켜져 있으면 실시간으로 받음) |
| 사진 유해성 판별 | `GOOGLE_VISION_API_KEY` | 판별 없이 게시(운영 환경이면 관리자 화면에 경고) |
| 인앱결제 | `IAP_MODE=live` + Google 서비스 계정 / Apple 키, 스토어 상품 등록 | 개발·시험: 개발용 검증 / 운영: 구매 처리 중단 |

### 본인확인(포트원)

1. 포트원 관리자 콘솔에서 본인인증 채널(다날·KG이니시스·KCP 중 계약한 곳)을 추가하고 Store ID, 채널 키, V2 API Secret 을 확인합니다.
2. 서버 환경변수에 넣고 `IDENTITY_PROVIDER=portone` 으로 바꿉니다. `PUBLIC_URL` 은 휴대폰에서 접속 가능한 https 주소여야 합니다.
3. 앱은 서버 설정을 읽어 자동으로 본인인증 화면(웹뷰)으로 바뀝니다. 인증이 끝나면 서버가 포트원에 결과를 직접 다시 조회해 휴대폰 번호 확인 → 성인 여부(연 나이 19세) 확인을 각각 기록합니다.
4. 같은 사람(CI)이 다른 번호로 또 가입하는 것은 막힙니다. 외국인은 출시 기본안에 따라 가입할 수 없습니다(`src/auth/identity.ts`).

### 푸시(Firebase Cloud Messaging)

1. Firebase 콘솔에서 프로젝트를 만들고 Android 앱(`kr.eumsoft.eumtalk`)과 iOS 앱을 등록합니다. `google-services.json` 은 넣지 않아도 됩니다.
2. **서버**: 프로젝트 설정 → 서비스 계정 → 새 비공개 키(JSON)를 `FCM_SERVICE_ACCOUNT` 에 한 줄로 넣고 `PUSH_PROVIDER=fcm`.
3. **앱**: 저장소 Settings → Secrets and variables → Actions → Variables 에 `FIREBASE_PROJECT_ID`, `FIREBASE_SENDER_ID`, `FIREBASE_API_KEY`, `FIREBASE_ANDROID_APP_ID`, `FIREBASE_IOS_APP_ID` 를 넣으면 CI가 푸시가 켜진 APK·AAB를 만듭니다. 직접 빌드할 때는 같은 값을 `--dart-define=이름=값` 으로 넘깁니다.
4. **iOS**: Firebase 콘솔에 APNs 인증 키(.p8)를 올리고, Xcode에서 Runner 타깃의 Signing & Capabilities 에 Push Notifications 가 켜져 있는지 확인합니다(`bootstrap.py` 가 권한 파일을 만들어 둡니다). 배포 빌드에서는 `ios/Runner/Runner.entitlements` 의 `aps-environment` 를 `production` 으로 바꿉니다.
5. 알림을 누르면 해당 대화방이 열립니다(인사 알림은 대화 탭). 앱이 켜져 있을 때는 시스템 알림을 띄우지 않습니다.

### 사진 유해성 판별

Google Cloud 콘솔에서 Cloud Vision API 를 켜고 API 키를 `GOOGLE_VISION_API_KEY` 에 넣습니다. 프로필·게시글·방 대표 사진만 게시 전에 검사하며(대화 사진은 신고로 대응), 선정성 "높음" 이상·폭력 "매우 높음"이면 올라가지 않습니다. 판별 서비스 장애 시에도 공개 사진은 올라가지 않습니다.

### Play 제출용 AAB 서명

업로드 키를 만들고(`keytool -genkeypair -keystore upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000`) 저장소 Secrets 에 넣습니다.

| Secret | 값 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 upload.jks` 결과 |
| `ANDROID_KEYSTORE_PASSWORD` | 키스토어 비밀번호 |
| `ANDROID_KEY_ALIAS` | `upload` |
| `ANDROID_KEY_PASSWORD` | 키 비밀번호 |

넣은 뒤에는 Actions 의 `eumtalk-play-aab` 결과물이 Play 콘솔에 올릴 수 있는 파일입니다. Secrets 가 없을 때 만들어지는 `eumtalk-aab-temp-key-not-for-play` 는 서명 과정 점검용이라 올릴 수 없습니다. 업로드 키 파일은 잃어버리지 않게 따로 보관하세요.
직접 빌드할 때는 `mobile/android/key.properties` 에 `storeFile`·`storePassword`·`keyAlias`·`keyPassword` 를 적고 `flutter build appbundle --release` 합니다.

스토어 상품 ID는 `products` 테이블과 같아야 합니다(기본: `eumtalk.points.100`, `eumtalk.points.550`, `eumtalk.points.1200`, `eumtalk.premium.monthly`).
가격과 결제 주기는 앱이 스토어에서 읽어 표시하므로 앱·서버에는 금액을 적지 않습니다.
스토어 서버 알림 주소: Google `…/v1/store/google/notifications?token=<STORE_WEBHOOK_TOKEN>`, Apple `…/v1/store/apple/notifications`.

## 6. Render 배포

1. 이 저장소를 GitHub에 올립니다.
2. Render → New → Blueprint → 저장소 선택. `render.yaml` 이 DB, Redis(Key Value), API 서버, 관리자 웹을 만듭니다.
3. 배포가 끝나면 `eumtalk-api` 의 주소(예: `https://eumtalk-api.onrender.com`)를 앱 빌드의 `API_BASE_URL` 로 사용합니다.
4. 관리자 토큰은 Render의 `eumtalk-api` → Environment → `ADMIN_TOKEN` 에서 확인합니다.

참고: 무료 플랜은 15분간 요청이 없으면 서버가 잠들어 첫 접속이 느리고, 그동안 WebSocket이 끊깁니다(앱은 자동 재연결 후 빠진 메시지를 받아옵니다). 무료 PostgreSQL은 기간 제한이 있으니 실제 시험 기간이 길면 유료 플랜을 쓰세요.

### 운영 전환

`APP_ENV=production` 으로 바꾸고 `IDENTITY_PROVIDER` 를 계약한 사업자로 지정합니다. 그 전까지 운영 환경에서는 가입이 열리지 않습니다.

## 7. 개인정보 관련 구현 메모

- 휴대폰 번호: 조회용 HMAC 해시 + AES-256-GCM 암호문으로만 저장. 실명은 받지 않고, 생년은 출생 연도만 `user_private` 에 저장.
- 다른 회원용 프로필은 `server/src/profile/public-profile.ts` 한 곳에서만 조립하며 `user_private`·좌표 컬럼을 SELECT 하지 않습니다.
- 위치: 약 500m 격자로 뭉갠 값만 저장. 거리는 SQL 안에서 `같은 동네 / 가까운 지역 / 같은 지역 / 같은 시·도` 구간으로만 바뀌어 나갑니다.
- 계정 삭제 시: 프로필 내용·사진·푸시 토큰·세션·휴대폰 번호·출생 연도는 즉시 삭제, 게시글·댓글은 비노출, 신고·조치 기록과 포인트·구매 기록은 보존(`account_deletions` 에 처리 내역 기록).
- 시·군·구 목록은 `migrations/002_*.sql` 기본 데이터입니다. 인천은 2026년 7월 개편안(제물포구·영종구·서해구·검단구) 기준으로 넣었는데 제 기억에 의존한 값이므로, 출시 전 반드시 행정안전부 최신 목록과 대조해 주세요.
